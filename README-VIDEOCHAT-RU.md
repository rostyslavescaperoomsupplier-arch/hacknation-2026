# Mewka Crew Video — WebRTC + WebSocket

Ветка для разработки: **`videochat`**. Код использует существующие `assistant/` и `mewka/`.

## Что реализовано

- Отдельная раскрываемая панель видеосвязи в Mewka; AI-чат не удаляется.
- Имя и канал экипажа; список участников онлайн.
- Входящие и исходящие индивидуальные звонки (1 на 1): принять, отклонить, отменить, завершить.
- Аудио/видео через браузерный WebRTC; отключение микрофона и камеры; аудио-only при отсутствии веб-камеры.
- WebSocket-сигнализация через **тот же Node HTTP-сервер на порту 8787**; без новых npm-зависимостей.
- Переподключение к WebSocket после разрыва; при потере связи текущий звонок завершается.
- Сокеты не транслируют видео, не хранят содержимое разговора.

## Установка

Из корня репозитория в ветке `videochat`:

```bash
cd mewka
npm install
cd ../assistant
npm install
npm run dev
```

Открой `http://localhost:5173` в двух браузерах или вкладках. В блоке **Mewka Crew Video**:

1. В первом окне введи имя `Captain`, канал `SHIP-01` и нажми «Join/Dołącz».
2. Во втором окне введи имя `Engineer`, тот же канал `SHIP-01` и подключись.
3. У Captain появится Engineer. Нажми **Call**.
4. Engineer нажимает **Answer** и разрешает доступ к камере и микрофону.
5. Captain разрешает доступ к камере и микрофону; начинается видеозвонок.
6. Проверь **Mute**, **Camera off**, **Hang up**.

Если хочешь проверить на двух компьютерах или телефонах, **оба должны видеть ваш сервер по сети**. Сервер обычно слушает на всех интерфейсах, но Vite dev-сервер по умолчанию доступен только с локальной машины. Для доступа с других устройств можно запустить `npm run dev -- --host 0.0.0.0` только если Vite-флаг действительно попадёт в команду Vite; проще собрать production (`npm run build && npm start`) и обращаться к `https://<адрес_судового_сервера>` через TLS reverse proxy. Для локальной проверки в двух вкладках HTTPS не требуется, потому что `localhost` считается безопасным контекстом.

**Важно:** `getUserMedia()` (камера/микрофон) работает только в **secure context**: обычно `https://` или `http://localhost`. При открытии `http://192.168.x.x:8787` на другом телефоне камера может быть недоступна. Нужен HTTPS с доверенным сертификатом на устройствах экипажа. Для демо допустимы две вкладки на `localhost`.

## Запуск серверных тестов

Из корня репозитория:

```bash
node --experimental-strip-types tests/crew-video.test.mjs
```

Для проекта требуется Node.js с поддержкой TypeScript type stripping (рекомендуется Node 22+). Тесты проверяют членство в комнате, изоляцию каналов, приглашения, busy, accept/reject, SDP/ICE сигнализацию, большие SDP и завершение звонка при отключении.

## Интернет / работа на корабле

По умолчанию `RTCPeerConnection` создаётся с `iceServers: []`, то есть **никакой внешний STUN/TURN не вызывается**. Это позволяет работать внутри одной доступной LAN, если устройства могут связаться напрямую и сеть не блокирует P2P-трафик. Связь между разными VLAN, NAT или изолированными Wi-Fi-клиентами может потребовать собственного TURN-сервера.

При наличии TURN добавь в `assistant/.env` перед запуском Vite, например:

```dotenv
VITE_CREW_ICE_SERVERS=[{"urls":"turn:turn.ship.local:3478","username":"demo","credential":"replace-me"}]
```

Это только пример конфигурации: TURN нужно отдельно установить, защитить и настроить. Не размещай секретные TURN-учётные данные в долгосрочной production-конфигурации фронтенда.

## Ограничения демо

- Это **1:1** звонки, не групповые конференции.
- Код канала **не аутентифицирует** пользователя, а лишь разделяет комнаты. Нет личных аккаунтов, прав доступа или E2E-подтверждения личности.
- Не подходит для экстренной, навигационной или другой safety-critical судовой связи.
- Нет записи вызовов, переписки, push-уведомлений, связи через интернет без TURN.
- Проверено серверное установление сигнализации; фактическая работа камеры и двухбраузерного WebRTC должна быть проверена на ваших устройствах.
- Имеющийся AI-чат продолжает работать при наличии API ключа Claude; видеозвонки от API Claude **не зависят**.
